# Выручай-комната — Telegram Mini App

> **Запуск для новичка — в [SETUP.md](SETUP.md)** (бот, токен Notion, хостинг, переменные).

Сервер (Node.js 22, без внешних зависимостей, данные в одном файле SQLite) + интерфейс клуба + бот.
Все права проверяет сервер: пароль админа и коды доступа в браузере больше не хранятся.

## Как это защищено
| Было | Стало |
|---|---|
| Пароль админа `777` в коде страницы | Организатор определяется по Telegram ID (`ADMIN_IDS`) |
| Кто угодно мог поставить `isAdmin`/`vrk-pro` в консоли | Доступ хранится на сервере, браузер его не определяет |
| Коды доступа лежали в Firebase, читались всеми | Участницам сервер коды не отдаёт; проверка — `POST /api/redeem`, ≤8 попыток за 10 минут |
| `notes.json` открытым файлом на сайте | Конспекты в базе, отдаются только после проверки доступа |
| База Firebase в «test mode» | Прямого доступа к базе нет |
| Имя в поле профиля = личность | Личность — подписанный Telegram `initData` (HMAC, срок жизни 24 ч) |
| Любой мог удалить/переписать чужие комментарии, голоса, оценки | Сервер проверяет diff: чужое менять нельзя, реакции и голоса — только от своего имени |

## Что бесплатно, что платно
- **Вступление в клуб — бесплатно** (экран приветствия: аватар, имя, цель на год).
- **Бесплатно для всех участниц:** каталог клуба, обсуждения, цитаты, вопросы, реакции, голосование, прогресс и статусы чтения, оценки, аудио-разборы, экранизации, таймер, профиль, уведомления.
- **Платно (закрыто на сервере):** конспекты (по коду книги или общему коду) и личная библиотека (общий код). Без доступа сервер отдаёт только витрину: оглавление и первый раздел конспекта, карточки книг личной библиотеки; текст конспектов и отзывы закрыты.
- Чтобы изменить состав платного, правьте `server/src/rules.js` (запись), `rootValue()` в `server/src/app.js` (чтение) и `isPro()` в интерфейсе.

## Запуск
1. **Бот.** @BotFather → `/newbot` → сохраните токен.
2. **Свой Telegram ID** (для организатора): напишите @userinfobot.
3. **Хостинг** с постоянным диском и HTTPS (Fly.io, Railway, Render, VPS). Нужен **один** экземпляр: SQLite — один файл.
   Docker: `docker build -t bookclub server && docker run -p 3000:3000 -v bookclub-data:/data --env-file .env bookclub`
4. **Переменные окружения:**
   ```
   BOT_TOKEN=123456:ABC...
   PUBLIC_URL=https://club.example.com
   ADMIN_IDS=111111111,222222222
   WEBHOOK_SECRET=<случайная строка>
   DB_FILE=/data/bookclub.sqlite
   NODE_ENV=production
   ```
5. **Настройка бота** (один раз): `npm run bot:setup` — webhook, кнопка «Клуб», команды.
6. **Первый вход организатора** заполняет каталог стартовыми книгами.
7. **Конспекты:** `DB_FILE=... node scripts/import-notes.js путь/к/notes.json` (текст очищается от разметки Notion).
8. **Данные из Firebase** (по желанию): экспорт JSON из консоли + `name-map.json` (`{"Анна": 123456789}`) →
   `node scripts/import-firebase.js export.json name-map.json`. Затем в Firebase поставьте правила `".read": false, ".write": false`.

## Разработка и тесты
`npm test` — 35 тестов (подпись initData, права, коды, ленты, голоса, бот, миграция).
Локально без Telegram: `DEV_AUTH=1 ADMIN_IDS=1 npm start`, затем `http://localhost:3000/?dev=1|Имя` (в production отключено).

## Обложки
Сервер ищет обложки в Google Books и Open Library и проверяет совпадение названия, автора и языка. Сам ставит только уверенное совпадение; остальное организатор выбирает вручную или загружает свою картинку (хранится в `covers/` рядом с базой). Ключ `GOOGLE_BOOKS_KEY` необязателен, но повышает лимиты.

## Конспекты из Notion
Сервер (раз в 15 минут и по кнопке) читает страницы «Конспекты по прочитанным книгам …» под «Читальней», переводит их в текст приложения и привязывает к книгам по названию (нечёткое сравнение: кавычки, порядок «автор/название», «ё» не мешают). Правка в Notion → обновлённый конспект в приложении. Дубли: побеждает самая свежая страница. Не нашли книгу — страница попадает в список организатора (привязать или создать книгу). Нужны `NOTION_TOKEN` и `NOTION_ROOT_PAGE_ID`; интеграция только на чтение.

## Организатору
- Профиль → «Настройки доступа»: общий код и коды по книгам. Участницы вводят код в приложении.
- Выдать доступ вручную (оплата переводом): `POST /api/admin/grant {userId, scope: "*" | "<id книги>"}`.
- Профиль → «Уведомление участницам»: рассылка от бота (получают те, кто запускал бота и не писал `/stop`).
- Резервная копия: копируйте файл базы (`sqlite3 bookclub.sqlite ".backup copy.sqlite"`).

## Ограничения
- Оплата цифровых материалов в Telegram должна идти через Telegram Stars — пока оставлены коды доступа и ссылка на Kaspi.
- Ленты (комментарии, цитаты) при одновременной правке реакций могут перезаписать друг друга; добавление новых записей безопасно.
- Автоматических напоминаний по расписанию нет — рассылка запускается вручную.
